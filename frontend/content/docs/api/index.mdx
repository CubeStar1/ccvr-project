The backend (`backend/`) is a FastAPI server over the VIDRA engine. It owns ingestion, chunk and
aggregate reads, search and question answering. The Next.js frontend is a client of this API —
there is nothing it can do with a video that this API cannot.

The routes and response shapes are the ones the original `core/` service had, so existing clients
keep working; where behaviour differs, the page says so.

**Base URL** — `http://127.0.0.1:8077` by default.
**Interactive docs** — `/docs` (Swagger); `/` redirects there.
**OpenAPI** — `/openapi.json`.

## Every endpoint

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/health` | Liveness, plus what this instance has loaded |
| `GET` | `/schema` | Analyzers, exclusive groups and aggregates |
| `GET` | `/analyzers` | Analyzers with descriptions, for an upload form |
| `POST` | `/uploads` | A one-time URL to upload a video file to |
| `POST` | `/videos/url` | Ingest a video from an `http(s)` URL or an upload |
| `GET` | `/jobs/{job_id}` | One job's progress and result |
| `GET` | `/videos/{video_id}` | One video's metadata |
| `DELETE` | `/videos/{video_id}` | Remove a video and everything produced for it |
| `GET` | `/videos/{video_id}/chunks` | Stored chunk output, scoped and paginated |
| `GET` | `/videos/{video_id}/chunks/{chunk_id}` | Everything produced for one chunk |
| `GET` | `/videos/{video_id}/aggregates` | Video-level results |
| `POST` | `/videos/{video_id}/aggregates` | Re-run aggregates without re-analysing |
| `GET` | `/videos/{video_id}/entities` | People linked across the video |
| `POST` | `/query` | Search for moments, optionally with a written answer |
| `POST` | `/ask` | Answer a question from moments plus the summary and chapters |
| `GET` | `/media/{video_id}` | Play the video (a redirect to a signed URL in production) |
| `GET` | `/media/{video_id}/poster.jpg` | The video's poster frame |

<Callout type="info">
  Not carried over from `core/`: multipart upload (`POST /videos`), `GET /videos` and `GET /jobs`.
  Upload with `POST /uploads` instead, and keep your own list of videos, as the frontend does in
  `video_core`.
</Callout>

## Conventions

**Everything is a read except uploads, ingest, delete and the aggregate re-run.** `POST /query` and
`POST /ask` are POSTs only because their bodies are too complex for a query string — they change
nothing.

**Ingestion is asynchronous.** Ingest and the aggregate re-run return `202` with a `job_id`. Poll
`GET /jobs/{job_id}` until `status` is `done` or `failed`.

**Ids are content hashes.** `video_id` is `sha256(bytes)[:16]`, so re-ingesting the same file is
recognised as the same video. See [Glossary](/docs/concepts/glossary).

**Reads are free.** `/videos/{id}`, `/chunks`, `/aggregates` and `/entities` read JSON files on
disk; they cost no model calls. `/query` costs one embedding call, plus an LLM call when it writes
an answer; `/ask` always makes one LLM call.

## A minimal session

```bash
# 1. What can this install do?
curl http://127.0.0.1:8077/schema

# 2. Ingest
curl -X POST http://127.0.0.1:8077/videos/url \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/clip.mp4","analyzers":"default_video,diarization"}'
# -> {"job_id":"d9b16a609ab1","status":"queued","source":"https://example.com/clip.mp4"}

# 3. Poll
curl http://127.0.0.1:8077/jobs/d9b16a609ab1
# -> ... "status":"done", "result": { "video_id": "dbf7af7300ab2484", ... }

# 4. Search
curl -X POST http://127.0.0.1:8077/query \
  -H 'Content-Type: application/json' \
  -d '{"text":"how to add a link","video_ids":["dbf7af7300ab2484"],"detail":"minimal","synthesize":false}'

# 5. Ask
curl -X POST http://127.0.0.1:8077/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"What happens in this video?","video_ids":["dbf7af7300ab2484"]}'
```
