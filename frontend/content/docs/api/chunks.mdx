`/query` searches. These endpoints **read**: fetch what was produced for each chunk rather than
retrieving against it. Everything is served from the video's folder on disk, so it costs nothing
— no model calls, no search.

---

## `GET /videos/{video_id}/chunks`

### Parameters

| Param | Type | Default | Notes |
|---|---|---|---|
| `analyzer` | string | all | Return only this analyzer's output on each chunk |
| `after` | float | – | Keep chunks ending after this second |
| `before` | float | – | Keep chunks starting before this second |
| `chunk_ids` | string | – | Comma-separated ids, e.g. `2,4,7` — batch fetch after a `minimal` search |
| `limit` | int | `50` | 1–500 |
| `offset` | int | `0` | Pagination |
| `verbose` | bool | `false` | Accepted for compatibility; no effect |

### Response

```json
{
  "video_id": "dbf7af7300ab2484",
  "analyzers": ["default_video", "diarization", "ocr"],
  "total": 24,
  "offset": 0,
  "limit": 1,
  "chunks": [
    {
      "chunk_id": 3,
      "start": 38.5,
      "end": 52.5,
      "timecode": "0:38-0:52",
      "default_video": {
        "description": "A full-screen educational graphic about HTML elements and heading tags appears on a black background…",
        "setting": "Full-frame animated presentation graphic…",
        "people": [],
        "objects": ["black triangle-pattern background", "thinking-face emoji graphic"],
        "actions": ["A thinking-face emoji appears, then shrinks as “HTML” is displayed below it."],
        "tags": ["html", "web development"]
      },
      "ocr": {
        "texts": [{ "text": "HTML", "context": "White label beneath the thinking-face emoji." },
                  { "text": "HTML ELEMENT", "context": "Label beneath the shocked-face emoji…" }],
        "summary": "The frames show a black background patterned with outlined triangles…"
      },
      "diarization": {
        "text": "when we make this content into an HTML element. We do this by adding an opening and closing tag…",
        "turns": [{ "speaker": "SPEAKER_00", "start": 38.3, "end": 52.5, "text": "…" }],
        "speakers": ["SPEAKER_00"]
      }
    }
  ]
}
```

`total` is the number of chunks matching the filters, not the page size — page with
`offset`/`limit` until you have them all.

### The batch-fetch pattern

<Callout type="info">
  This is the second half of the cheap retrieval pattern. Run `/query` at `detail=minimal` to
  decide which moments matter, then fetch only those here with `chunk_ids=2,4,7`.
</Callout>

```bash
curl "http://127.0.0.1:8077/videos/dbf7af7300ab2484/chunks?chunk_ids=2,4,7" \
  -H "X-Core-Token: $TOKEN"
```

### Errors

| Code | Cause |
|---|---|
| `400` | `chunk_ids` is not comma-separated integers, or `analyzer` is not a known analyzer |
| `404` | Unknown video |

## `GET /videos/{video_id}/chunks/{chunk_id}`

One chunk, with every analyzer's output on it — the same object as one entry of `chunks` above.

**404** if the chunk does not exist in that video.

<Callout type="warn">
  `chunk_id` is a position within one video's chunk list — every video has a chunk 0, and the same
  id means a different moment after a re-chunking. Always pair it with a `video_id`, and never
  persist one across a re-index.
</Callout>
