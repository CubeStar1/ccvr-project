The backend authenticates with a **shared secret**, checked on every route that reads or writes
a video.

```bash
curl http://127.0.0.1:8077/videos/dbf7af7300ab2484 \
  -H "X-Core-Token: $CORE_API_TOKEN"
```

Set `CORE_API_TOKEN` in `backend/.env`, and the same value as `CORE_API_TOKEN` in
`frontend/.env.local`. Unset means **open**, which is the right default for a machine-local dev
server and the wrong one for anything reachable: without it, whoever can open the port has the
whole corpus.

## Open paths

These stay reachable without the token, so a deployment can be checked and explored:

| Path | Why |
|---|---|
| `/` | Redirects to `/docs` |
| `/health` | Liveness must work for a load balancer |
| `/docs`, `/openapi.json` | The API definition |
| `/media/…` | Poster images, which a browser loads directly in an `<img>` tag |

Everything else returns `401`:

```json
{ "detail": "Invalid or missing X-Core-Token" }
```

<Callout type="warn">
  **This is not an authorisation model.** There are no users in the backend, no projects, and no
  row-level security — one token grants the whole corpus. It is the boundary that stops the port
  from being one.
</Callout>

## Building multi-tenant on top

The backend is single-tenant by design. Every deployment that serves more than one user puts an
application layer in front, and that layer owns:

1. **Identity** — who is calling.
2. **Ownership** — which `video_id` values that caller may touch. Store them; the backend will not.
3. **Explicit scoping** — pass `video_ids` on every `/query` and `/ask` call. Omitting it searches
   *everything in the install*.
4. **Delete safety** — `video_id` is a content hash, so two users who uploaded the same bytes
   share one video. Count references before calling `DELETE /videos/{video_id}`.

The reference implementation of exactly this is in
[Building a client](/docs/api/client-integration): rows in Postgres with RLS, a single scope
resolver every tool passes through, and the backend only ever called with explicit ids.

## Deployment checklist

- [ ] `CORE_API_TOKEN` set in the backend, and the same value in the client.
- [ ] The backend's port not publicly routable — the application layer is the only client that
      needs it.
- [ ] `BACKEND_PUBLIC_URL` set to the address browsers use, so posters load.
- [ ] The token held server-side only. A browser that can send it can read every video.
