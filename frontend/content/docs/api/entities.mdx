A moment can only say "a person in grey is at the counter". This endpoint is what connects those
sightings into one person, across the whole video, with a written account of what they did.

Requires the `people` analyzer and the `entities` aggregate (`VIDRA_TIER=llm`).

---

## `GET /videos/{video_id}/entities`

| Param | Type | Default | Notes |
|---|---|---|---|
| `min_appearances` | int | `1` | Only people seen in at least this many chunks |

```bash
curl "http://127.0.0.1:8077/videos/6b9ca6e1a1b2c3d4/entities?min_appearances=2" \
  -H "X-Core-Token: $TOKEN"
```

```json
{
  "video_id": "6b9ca6e1a1b2c3d4",
  "total": 1,
  "entities": [
    {
      "entity_id": "e000",
      "label": "woman in a light grey T-shirt",
      "name": "woman in a light grey T-shirt",
      "appearances": 3,
      "chunk_ids": [0, 4, 9],
      "first_seen": 0.0,
      "last_seen": 141.2,
      "observed_s": 41.5,
      "narrative": "She works the right-hand register for most of the recording…",
      "description": "She works the right-hand register for most of the recording…",
      "account": { "text": "…", "narrative": "…" },
      "doubts": [],
      "mentions": [ "…each sighting: chunk_id, sampler_id, text, context" ],
      "timeline": { "observed_seconds": 41.5, "spans": [[0.0, 13.8], [52.1, 66.0], [127.4, 141.2]] }
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `entity_id` | Stable within this video only |
| `label` / `name` | Short identifying description |
| `appearances` | How many chunks this person was seen in |
| `chunk_ids` | Which ones — feed these to `GET /videos/{id}/chunks?chunk_ids=…` |
| `first_seen`, `last_seen` | Seconds |
| `narrative` / `description` | What they did across the video, written after linking |
| `doubts` | Anything the model wasn't sure was the same person |
| `mentions` | Every sighting that was linked into this entity |
| `timeline` | Total observed time and the chunk spans, for drawing presence on a timeline |

<Callout type="info">
  Use `min_appearances=2`. Someone seen once is already fully described by their chunk; the value
  here is the people who were actually *followed* across the video.
</Callout>

## How linking works

Every sighting from the vision model's chunk descriptions is embedded. Sightings are linked into
one entity when their embeddings match closely enough — the threshold is calibrated per video —
and only then does the LLM write the account of each entity.

The same method produces `object_entities` (from `object_detection`) and `text_entities` (from
`ocr` — titles, URLs, labels that recur on screen). Read those through
[`GET /videos/{id}/aggregates`](/docs/api/aggregates); they carry the same fields.

<Callout type="warn">
  **Cross-video entity linking is not built.** Entity ids are meaningful within one video only.
  Two videos of the same person produce two unrelated ids.
</Callout>

## Errors

| Code | Cause |
|---|---|
| `400` | The video has no `entities` aggregate — it was analysed without `people`, or below the `llm` tier. The message lists what it does have |
| `404` | Unknown video |
