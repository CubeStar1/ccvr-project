`POST /query` finds **moments**. For a question whose answer is a conclusion rather than a
location, use [`POST /ask`](/docs/api/ask).

`application/json`.

## Body

| Field | Type | Default | Notes |
|---|---|---|---|
| `text` | string | *required* | The search query |
| `video_ids` | `string[]` \| null | `null` | Restrict to these videos. **`null` searches every video in the install** |
| `analyzer` | string | `default_video` | `default_video` searches everything; another picture analyzer searches only its own descriptions |
| `limit` | int | `5` | 1–50 |
| `synthesize` | bool | `true` | Whether to write an answer over the hits |
| `detail` | string | `standard` | `minimal` \| `standard` \| `full` |
| `field` | string | `combined` | Accepted for compatibility; ignored |
| `score_threshold` | float \| null | `null` | Accepted for compatibility; ignored |
| `filters` | object | `{}` | Must be empty — a non-empty value is a `400` |

## Example

```bash
curl -X POST http://127.0.0.1:8077/query \
  -H "X-Core-Token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "how do you add a link",
    "video_ids": ["dbf7af7300ab2484"],
    "limit": 5,
    "synthesize": true
  }'
```

```json
{
  "query": "how do you add a link",
  "analyzer": "default_video",
  "field": "combined",
  "detail": "standard",
  "answer": "…written from the hits, citing each moment as m:ss…",
  "results": [ { "…": "SearchResult" } ]
}
```

<Callout type="info">
  `answer` is `null` when `synthesize` is false or nothing matched. It is never written from an
  empty result set. With `synthesize` on, the answer is written from the hits at `full` detail
  even when `detail` asks for less.
</Callout>

## How it ranks

Each chunk's descriptions and transcript are matched against the query two ways — embedding
similarity with `text-embedding-3-small`, and keyword match — and the rankings are fused per chunk
with reciprocal rank fusion. See [Retrieval](/docs/concepts/retrieval).

`score` is that fused score. It is only meaningful for ordering hits within one response.

## `detail` — how much comes back

A browser and an agent want opposite things from the same hit.

| Level | Contents |
|---|---|
| `minimal` | `video_id`, `chunk_id`, `start`, `end`, `timecode`, `score`, 240-character `snippet` |
| `standard` | plus `video_url`, `description`, `people`, `objects`, `actions`, `tags`, `speakers`, `turns`, `people_count` |
| `full` | plus `text`, `persons`, `detections`, `texts` |

The agent pattern: `detail=minimal` to choose, then
[`GET /videos/{id}/chunks?chunk_ids=…`](/docs/api/chunks) to read the few that matter.

## SearchResult

| Field | Type | Notes |
|---|---|---|
| `video_id` | string | Content hash of the source file |
| `chunk_id` | int | Index **within its video** — only meaningful with `video_id` |
| `start`, `end` | float | Seconds; use these to seek |
| `timecode` | string | `m:ss-m:ss`, e.g. `"2:31-2:44"` |
| `score` | float | Fused rank score |
| `snippet` | string | `minimal` only — the first 240 characters of the description or transcript |
| `video_url` | string | Where the video plays from |
| `description` | string | The `default_video` description, or another analyzer's summary |
| `people`, `objects`, `actions`, `tags` | `string[]` | From `default_video`; empty when it didn't run |
| `speakers` | `string[]` | Speakers heard in the chunk (`diarization`) |
| `turns` | `object[]` | `{speaker, start, end, text}` |
| `people_count` | int \| null | From the `people` analyzer |
| `text` | string | `full` only — the chunk's transcript |
| `persons`, `detections`, `texts` | `object[]` | `full` only — `people`, `object_detection` and `ocr` output |

<Callout type="info">
  The payload is self-sufficient: everything needed to cite and play a moment is on the hit.
</Callout>

## Errors

| Code | Cause |
|---|---|
| `400` | Unknown `analyzer` or `detail`; a non-empty `filters` |
| `401` | Missing or wrong token |
