## `GET /videos/{video_id}`

One video's metadata.

```json
{
  "video_id": "dbf7af7300ab2484",
  "filename": "clip.mp4",
  "video_url": "https://<project>.supabase.co/storage/v1/object/public/project-assets/…/clip.mp4",
  "poster_url": "http://127.0.0.1:8077/media/dbf7af7300ab2484/poster.jpg",
  "storage_path": "/path/to/backend/data/sources/dbf7af7300ab2484.mp4",
  "source_url": "https://<project>.supabase.co/storage/v1/object/public/project-assets/…/clip.mp4",
  "size_bytes": 16135088,
  "preset": "audio_video",
  "params": { "mode": "preset", "preset": "audio_video" },
  "chunk_config": "scene",
  "analyzers": ["default_video", "diarization", "ocr"],
  "aggregates": ["chapters", "coverage", "events", "ner", "sentiment", "speaker_stats",
                 "stats", "summary", "text_entities"],
  "chunks": 24,
  "duration": 311.433
}
```

| Field | Notes |
|---|---|
| `video_url`, `source_url` | Where it was ingested from. The video plays from here, so the URL must stay reachable |
| `storage_path` | The backend's downloaded copy |
| `chunk_config` | The chunking policy actually used: `scene`, `vad`, `speaker` or `uniform` |
| `analyzers` | Which passes ran on this video — the predicate for "can it answer X?" |
| `aggregates` | Which video-level results are stored |
| `params` | The chunking options the ingest was given |

**404** for an unknown id.

<Callout type="info">
  There is no `GET /videos` listing. The backend has no notion of who owns what, so a client
  should keep its own list — the frontend uses its `video_core` table.
</Callout>

## `DELETE /videos/{video_id}`

Removes a video completely: its folder under `data/out/` (and with it the search index), the
downloaded file, the poster and the ingest record.

```json
{ "video_id": "dbf7af7300ab2484", "deleted": true }
```

The source URL is not touched — a file in Supabase Storage stays there until the frontend removes
it.

<Callout type="warn">
  `video_id` is a content hash, so two callers who ingested the same bytes are referring to the
  **same** video. Whoever owns the application-side rows has to decide that nothing else still
  points at it before calling this — the backend has no notion of who else is interested.
</Callout>

**404** for an unknown id.

---

## `GET /media/{video_id}/poster.jpg`

The frame one second into the video, as a JPEG. Open — no token required, so it works in an
`<img>` tag. The `poster_url` in responses points here, built from `BACKEND_PUBLIC_URL`.

**404** if the video has no poster.
