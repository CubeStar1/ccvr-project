`/query` finds moments; `/ask` answers questions, which usually needs more than moments.

`application/json`.

## Body

| Field | Type | Default | Notes |
|---|---|---|---|
| `question` | string | *required* | Natural-language question |
| `video_ids` | `string[]` \| null | `null` | Restrict to these videos. `null` uses every ingested video |
| `analyzer` | string \| null | `null` | Narrow the supporting search to one analyzer, as in `/query`. `null` searches everything |
| `limit` | int | `6` | Supporting moments to retrieve, 1–20 |

## Example

```bash
curl -X POST http://127.0.0.1:8077/ask \
  -H "X-Core-Token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "What does this video teach, in order?",
    "video_ids": ["dbf7af7300ab2484"]
  }'
```

```json
{
  "question": "What does this video teach, in order?",
  "answer": "It starts with HTML foundations and page structure (0:00), then elements, attributes and forms (1:21), data attributes and container elements (3:45), and ends on semantic HTML (4:33)…",
  "sources": {
    "dbf7af7300ab2484": { "aggregates": ["summary", "chapters"] }
  },
  "results": [ { "…": "supporting moments, shaped as SearchResult at detail=full" } ]
}
```

## What goes into the answer

1. **Moments** — the `limit` chunks most relevant to the question, found exactly as `/query` finds
   them.
2. **The overview** — the `summary` and `chapters` aggregates of each video in scope (up to five
   videos), when they exist.

Both go to the backend's LLM with instructions to answer from that evidence only, cite moments as
`m:ss`, and say plainly when the evidence doesn't answer the question. `sources` says which
aggregates were read for which video — worth surfacing, because it explains why an answer knows
something no single moment says.

## Why this over `/query`

A search returns the moments most similar to a phrase. That is the right tool for "find the part
where…" and the wrong one for "what is this video about" — which needs the whole video, not the
five moments that best match the word "about". The summary and chapters already contain that
overview.

## Empty cases

```json
{ "question": "…", "answer": null, "sources": {}, "results": [], "error": "Nothing analysed in scope yet." }
```

Returned as `200` when no video in scope has any moments or overview to answer from — it is an
answer about the corpus, not a request failure.

## Errors

| Code | Cause |
|---|---|
| `400` | Unknown `analyzer` |
| `401` | Missing or wrong token |
