## Symptoms

<Accordions type="single">

<Accordion title="Cannot reach the analysis backend">

The frontend cannot connect to the backend. Check, in order:

1. Is the backend running? `curl http://127.0.0.1:8077/health`
2. Does `CORE_API_URL` in `.env.local` match the port it actually bound?
3. Does `CORE_API_TOKEN` match on both sides? A mismatch is a `401`, not a connection error —
   the message will say `Invalid or missing X-Core-Token`.

</Accordion>

<Accordion title="Opening the backend in a browser shows Not Found">

The page says `{"detail":"Not Found"}`: you're on a path that doesn't exist. `/` redirects to the API docs at `/docs`; the app itself is
the frontend, at `http://localhost:3000`.

</Accordion>

<Accordion title="Sign-up asks for 6 digits but the email has 8">

The sign-up form's code length must match Supabase's **Email OTP Length** (Authentication →
Email). It is set to 8 in `frontend/components/supaauth/signup.tsx` (`OTP_LENGTH`); change it if
your project sends a different length.

</Accordion>

<Accordion title="A video is stuck on Analyzing">

Usually normal. A five-minute video takes around five minutes, and the first ingest after
installing also downloads several model weights. Uploads are processed one at a time, so a second
video stays `queued` until the first finishes.

Check `stage` on the row or the job to see what it is doing: `transcribing`, `chunking`,
`sampling`, `analyzing`, `indexing` or `aggregating`. If it hasn't moved for a long time, read the
backend's terminal output.

</Accordion>

<Accordion title="A video failed with 'the server restarted while this job ran'">

Exactly what it says: the backend stopped while that ingest was in progress. Jobs are saved to
disk, so the backend knows the job never finished and reports it as failed instead of leaving it
hanging. **Re-index** the video.

</Accordion>

<Accordion title="A job failed with an OpenAI 401 or AuthenticationError">

`OPENAI_API_KEY` in `backend/.env` is wrong, revoked or out of credit. Test it:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"
```

`200` means the key works. Restart the backend after changing `.env`.

</Accordion>

<Accordion title="diarization fails to load">

Its pyannote models are gated. Accept the terms on
[pyannote/speaker-diarization-3.1](https://huggingface.co/pyannote/speaker-diarization-3.1) and
[pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0) with the account
the token belongs to, then set `HF_TOKEN` in `backend/.env`.

</Accordion>

<Accordion title="The agent says a video isn't searchable">

Its status is not `ready`. That is intended: the agent is told to say a video is still being
analysed rather than searching it and returning nothing.

</Accordion>

<Accordion title="The agent says it cannot answer that for this video">

The video was analysed without the analyzer that question needs — no `diarization` or
`transcript`, so nothing to quote; no `people`, so no linked people.

Re-index with the missing analyzer. Aggregates are recomputed as part of the new ingest.

</Accordion>

<Accordion title="Search returns nothing useful for something that is clearly in the video">

1. **The wrong `analyzer`.** `default_video` searches everything; `ocr`, `people` or
   `object_detection` searches only that analyzer's descriptions, and returns nothing if it
   never ran.
2. **The wrong `video_ids`.** Check the video is tagged, or that nothing is tagged.
3. **Try both wordings.** Search is hybrid — quote the exact words for something said or shown
   on screen, or describe it in a full phrase for something seen.

</Accordion>

<Accordion title="/query returns 400: filters are not supported">

The backend doesn't support structured filters. Drop `filters`, and narrow with `video_ids`,
`analyzer` and the query text.

</Accordion>

<Accordion title="An upload fails before analysis starts">

The browser sends the file straight to the URL the backend issued. Check the browser's network
tab for the `PUT`:

- **Blocked by CORS** — the page's origin isn't in the backend's `FRONTEND_ORIGINS`. Add it
  (comma-separated) and restart the backend; with blob storage, the backend re-applies the
  storage account's CORS rules on startup.
- **`403` from Azure** — the signed URL expired (30 minutes) or the machine's clock is far off.
  Upload again.
- **`404` from the backend** — the upload id was already used or has expired. Upload again.

</Accordion>

<Accordion title="An aggregate is missing">

Check whether it was **skipped** rather than failed. An aggregate whose analyzer the video lacks
is skipped by design:

| Aggregate | Needs |
|---|---|
| `speaker_stats` | `diarization` |
| `entities` | `people` |
| `object_entities` | `object_detection` |
| `text_entities` | `ocr` |

The LLM aggregates (`summary`, `chapters`, `events` and the three entity ones) also only run when
`VIDRA_TIER` is `llm`, the default.

</Accordion>

<Accordion title="Videos or posters don't load">

Both are served from the backend at `/media/<id>` and `/media/<id>/poster.jpg`, and the addresses
are built from `BACKEND_PUBLIC_URL` when the video is ingested. If the browser reaches the backend
somewhere else, set `BACKEND_PUBLIC_URL` and re-index.

With blob storage, `/media/<id>` redirects to a signed Azure URL; if that fails, check the
storage account still exists and the connection string is current.

</Accordion>

<Accordion title="Changes to the backend seem to have no effect">

An old server may still be holding the port, so requests hit stale code. Free it and start again:

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
lsof -ti:8077 | xargs kill
```

</Tab>
<Tab value="PowerShell">

```powershell
Get-NetTCPConnection -LocalPort 8077 -State Listen |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
```

</Tab>
</Tabs>

</Accordion>

<Accordion title="A transcript contains text that was never spoken">

Whisper hallucinates on non-speech audio. Voice-activity filtering is on, which handles most of
it; long stretches of music or room tone are the usual trigger.

</Accordion>

</Accordions>

## Resetting

Everything the backend writes lives under `backend/data/`:

<Tabs items={['bash', 'PowerShell']}>
<Tab value="bash">

```bash
rm -rf backend/data
```

</Tab>
<Tab value="PowerShell">

```powershell
Remove-Item -Recurse -Force backend/data
```

</Tab>
</Tabs>

<Callout type="warn">
  Without blob storage this deletes every video file and its analysis — the only copies.
  Application rows survive in Postgres with nothing behind them; delete them and upload again.
  With blob storage configured, the local folder is only a cache, and deleting it loses nothing.
</Callout>

## Environment notes

These look like problems and aren't:

- **`objc[…]: Class AVF… is implemented in both …` on macOS.** PyAV and OpenCV each bundle
  ffmpeg's libraries. Harmless.
- **A `yolo11n.pt` file appears in `backend/`.** Ultralytics downloads weights into the working
  directory on first use. `*.pt` is git-ignored.
- **The first ingest is much slower than the rest.** Whisper, pyannote, GLiNER, DistilBERT and
  the detectors download on first use, then load from cache.

## Verifying against a live server

Verify changes against a running server, not by reading code: ingest a short clip, then call
`/query` and `/ask` on it. Several problems only show up over HTTP.
