## Backend

Read from `backend/.env` (and the process environment).

### Required

| Variable | Purpose |
|---|---|
| `OPENAI_API_KEY` | Frame descriptions, embeddings, `/query` and `/ask` answers, and the written aggregates |
| `HF_TOKEN` | Speaker diarization; its pyannote models are gated. Only needed if you use `diarization` |

### Optional

| Variable | Default | Purpose |
|---|---|---|
| `CORE_API_TOKEN` | – | Shared secret required on every non-public route. **Set this for any deployment reachable from off-box** |
| `VIDRA_TIER` | `llm` | The costliest aggregates an ingest runs: `free`, `local` or `llm`. See [Aggregators](/docs/concepts/aggregators) |
| `BACKEND_DATA` | `backend/data` | Where everything is written. Wiping it is a full reset |
| `BACKEND_PUBLIC_URL` | `http://127.0.0.1:8077` | How a browser reaches the backend. Poster URLs are built from it, so change it when the backend is not on localhost |

### What's in the data folder

| Path | Holds | Regenerable |
|---|---|---|
| `out/<video_id>/` | VIDRA's output: media info, timeline, transcript, descriptions, embeddings, aggregates. Also the search index | Only by re-ingesting |
| `sources/<video_id>.<ext>` | The downloaded video | Yes — it's a copy of the source URL |
| `videos/<video_id>.json` | What was asked for at ingest, and where the video came from | No |
| `jobs/<job_id>.json` | Job state, so a restart does not lose it | Not needed after the job ends |
| `posters/<video_id>.jpg` | One frame for the video card | Yes |

<Callout type="info">
  `out/` and `videos/` together are the analysis. Back those two up if anything.
</Callout>

### Changing models

Every model role is set in one line of `backend/engine.py`:

```python title="backend/engine.py"
MODELS = Models()                    # OpenAI for every role; the key comes from .env
```

The roles are `vlm` (frame descriptions), `llm` (aggregates and answers), `embedder` and
`visual_embedder`. VIDRA can also use Anthropic, local models, or any OpenAI-compatible server for
these — see `vidra/README.md`. Changing the embedder means re-ingesting, since stored vectors
must come from the same model as the query.

## Frontend

```bash title="frontend/.env.local"
# Supabase — rows, auth, and the project-assets bucket
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
NEXT_PUBLIC_SUPABASE_ADMIN=""            # service-role key

# The analysis backend (backend/, built on vidra/)
CORE_API_URL="http://127.0.0.1:8077"
CORE_API_TOKEN=""                        # must match CORE_API_TOKEN in backend/.env

# Model providers — whichever you want in the model picker
OPENAI_API_KEY=""
GOOGLE_GENERATIVE_AI_API_KEY=
XAI_API_KEY=""
GROQ_API_KEY=""
CEREBRAS_API_KEY=""
LMSTUDIO_BASE_URL="http://localhost:1234/v1"   # local LM Studio server, no key needed

# Transactional email (optional)
NEXT_PUBLIC_RESEND_API_KEY=
NEXT_PUBLIC_RESEND_DOMAIN=

NEXT_PUBLIC_APP_NAME="FalconVQA"
NEXT_PUBLIC_APP_ICON='/next.svg'
```

`CORE_API_URL` and `CORE_API_TOKEN` are read server-side only, in `lib/core/client.ts`. That
client is never imported into a client component: the backend has no per-user auth, so every
call is made by a route that has already checked ownership and resolved which video ids the
caller may touch.

### Available models

The chat model picker is defined in `app/agent/lib/ai/models.ts`. It is independent of the
backend's models — the picker chooses who runs the agent loop, not who describes frames.

| Provider | Models |
|---|---|
| OpenAI | `gpt-4o-mini`, `gpt-4.1-mini`, `gpt-5.4-mini` |
| Google | `gemini-2.5-flash` |
| Groq | `llama-3.3-70b-versatile`, `openai/gpt-oss-120b`, `openai/gpt-oss-20b`, `moonshotai/kimi-k2-instruct` |
| Cerebras | `llama3.1-8b`, `gpt-oss-120b` |

A provider whose key is unset simply fails when selected; nothing else breaks.

## Security posture

<Callout type="warn">
  **The backend has no users, no projects, and no row-level security.** Whoever can reach the
  port can read every video in it. `CORE_API_TOKEN` is a boundary, not an authorisation model —
  it stops the port from being one. All per-user scoping happens in the frontend: RLS on
  `video_core`, plus every agent tool resolving the ids it is allowed to touch through a single
  choke point before calling the backend.
</Callout>

For a deployment:

1. Set the same `CORE_API_TOKEN` in `backend/.env` and `frontend/.env.local`.
2. Do not expose the backend's port publicly. The frontend is the only client that needs it.
3. Set `BACKEND_PUBLIC_URL` to the address browsers use, so poster images load.

`/`, `/health`, `/docs`, `/openapi.json` and `/media/…` (poster images) stay open regardless, so a
deployment can be checked without the secret.

<Callout type="warn">
  Keep `.env` and `.env.local` out of git — the root `.gitignore` already excludes them. If a key
  is ever pasted somewhere public, rotate it in the provider's dashboard.
</Callout>
