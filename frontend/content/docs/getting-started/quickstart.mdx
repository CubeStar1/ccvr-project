This gets both servers running on one machine. For the full explanation of every option, see
[Installation](/docs/getting-started/installation) and [Configuration](/docs/getting-started/configuration).

## Before you start

| What | Why |
|---|---|
| [uv](https://docs.astral.sh/uv/) | Installs Python 3.12 and the backend's dependencies |
| ffmpeg | Audio and video decoding (`brew install ffmpeg` on macOS) |
| Node 20+ | The Next.js frontend |
| An OpenAI API key | Frame descriptions, embeddings, answers, and the written aggregates |
| A Hugging Face token | Speaker diarization — its pyannote model is gated |
| A Supabase project | Auth, Postgres for projects/conversations/videos, and storage for uploads |

A GPU helps but is not required: Apple Silicon (`mps`), CUDA and CPU all work.

<Steps>

<Step>

### Start the backend

```bash
cd backend
uv sync
```

Create `backend/.env`:

```bash title="backend/.env"
OPENAI_API_KEY=sk-...
HF_TOKEN=hf_...
```

Then run it:

```bash
uv run uvicorn app:app --port 8077
```

Check `http://127.0.0.1:8077/health` — `status` is `ok` and `ffmpeg` is a path. Opening
`http://127.0.0.1:8077/` redirects to the interactive API docs.

</Step>

<Step>

### Set up the database

Run `frontend/lib/supabase/migrations/schema.sql` in the Supabase SQL editor. It creates
`projects`, `conversations`, `messages`, `video_core` (the app's view of an analysed video), the
`project-assets` bucket, and the RLS policies.

Safe to re-run: everything is `IF NOT EXISTS` / `DROP … IF EXISTS`.

</Step>

<Step>

### Start the frontend

```bash
cd frontend
npm install
cp env.example .env.local
```

Fill in `.env.local`:

```bash title="frontend/.env.local"
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
NEXT_PUBLIC_SUPABASE_ADMIN=eyJ...          # service-role key

OPENAI_API_KEY=sk-...                      # plus any other provider you want in the model picker

CORE_API_URL=http://127.0.0.1:8077
CORE_API_TOKEN=                            # must match CORE_API_TOKEN in backend/.env, if set
```

```bash
npm run dev                                # http://localhost:3000
```

<Callout type="info">
  Both servers have to be running. The frontend cannot ingest or retrieve on its own — every
  video operation is a call into the backend.
</Callout>

</Step>

<Step>

### Create a project and upload a video

Register, enter the code from the confirmation email, go to `/projects`, and create a project.
In the workspace, click **Upload** and either drop a file in or paste a direct video URL.

The upload dialog asks two things that matter:

- **Which analyzers to run.** `default_video` (scene description) plus `diarization`
  (speech with speakers) is a good default; add `ocr` for slides or screen recordings. See
  [Analyzers](/docs/concepts/analyzers).
- **How to chunk.** Leave it on the `Audio + video` preset. See
  [Chunking](/docs/concepts/chunking).

</Step>

<Step>

### Wait for indexing

Each card shows a status pill moving through `Queued` → `Analyzing` → `Ready`. The grid polls,
and each poll reconciles the row against the backend's job.

Indexing takes minutes: a five-minute video with `default_video`, `diarization` and `ocr` took
about five and a half minutes on an Apple Silicon laptop. The first run is slower, because it
downloads the Whisper, pyannote and other model weights. Only `Ready` videos are searchable.

</Step>

<Step>

### Ask something

Type into the prompt box, or click a suggestion card. Use the **Videos** control next to the
model selector to tag exactly which videos to search; tagged videos appear as chips above the
input.

Try:

- *"What happens in this video?"* — the agent calls `ask_video`
- *"Find the moment where they explain headings"* — `search_moments`
- *"Show me clips of that"* — `show_clips`, which opens the artifact panel

Clips open in the right-hand panel: a player on top, the clip list below. Click any row to jump
to that moment; **Play all** plays them back to back.

</Step>

</Steps>
