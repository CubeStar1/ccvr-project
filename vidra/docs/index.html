VIDRA

A Python library that turns a video into a searchable index of moments, and answers questions about the whole video.

  • video_rag cuts a video into time chunks, keeps a few frames per chunk, has a vision model describe them, transcribes the audio and embeds the text. A search returns the matching chunks with their times.
  • aggregates reads what video_rag wrote and answers questions about the whole video: counts, speakers, a summary, chapters, events, named entities, and who or what keeps appearing.
video.mp4 ──► video_rag ──► data/out/<video_id>/ ──► search("a customer paying") ─► moments (files, one per stage) │ └──► aggregates ──► summary, chapters, people, ...

Each stage writes a file in the video's folder; search reads from a database, which can be that folder. Models are objects you pass in: classes for OpenAI, Anthropic and local models are included, and you can write your own.

Install

VIDRA supports Python 3.11 to 3.14. FFmpeg comes bundled with PyAV.

git clone https://github.com/Vex-V/FalCONvar.git
cd FalCONvar
pip install ".[all]"

pip install ".[all]"botheverything

pip install -r requirements.txt installs the exact tested versions of the dependencies, but not vidra itself.

On Windows, pip installs a CPU-only PyTorch by default. For an NVIDIA GPU, add --extra-index-url https://download.pytorch.org/whl/cu130. Without a GPU everything still runs, more slowly (see Hardware).

Keys and configuration

API keys are read from environment variables. A .env file is read only if you call vidra.configure(env_file=".env"). You can also pass keys directly: OpenAI(api_key=...), Supabase(url=..., key=...).

VariableRead by
OPENAI_API_KEYOpenAI, OpenAIEmbedder (also accepted as OPENAI_API)
ANTHROPIC_API_KEYAnthropic
HF_TOKENthe first download of pyannote's gated speaker model; not needed once cached
SUPABASE_URL, SUPABASE_SECRET_KEY, SUPABASE_PUBLISHABLE_KEYSupabase: writes use the secret key, searches the publishable one
VIDRA_DATAwhere output goes (default data/ in the checkout, else ~/.vidra)
VIDRA_WEIGHTSwhere checkpoints are cached (default weights/)

The repository's .env.example lists all of them.

configure()

vidra.configure(data_root=None, weights=None, env_file=None, hf_token=None)

Call configure() once, before running anything. Arguments left as None are not changed.

ArgumentMeaning
data_rootWhere output, custom questions (prompts.json) and custom aggregates (aggregates.json) live. Outranks VIDRA_DATA.
weightsWhere checkpoints are cached. Outranks VIDRA_WEIGHTS.
env_fileA .env file to read now. Never overrides a variable already set; a missing file is refused.
hf_tokenA Hugging Face token for gated downloads, for this process only.
import vidra

vidra.configure(env_file=".env", data_root="/srv/vidra")
print(vidra.__version__)

Quickstart

Index a video, search it, then summarise it and split it into chapters. Needs vidra[all] and OPENAI_API_KEY.

import vidra
from vidra import Folder, LocalEmbedder, Models, OpenAI, aggregates
from vidra.video_rag import search, video_rag
from vidra.video_rag.samplers import Clip, Yolo

vidra.configure(env_file=".env")
models = Models(vlm=OpenAI("gpt-6-luna"), llm=OpenAI("gpt-6-luna"),
                embedder=LocalEmbedder())
db = Folder("data/out")                     # search the output folder; no server

run = video_rag("shop.mp4", "data/out", policy="scene", sampler=[Clip(), Yolo()],
                models=models, database=db)

moments, notes = search("a customer paying in cash", run.video_id,
                        models=models, database=db)
for m in moments:
    print(f"{m.start_ts:.0f}-{m.end_ts:.0f}s", m.hits[0]["content"][:80])

d = run.folder
video = aggregates.record(timeline=d / "timeline.json", transcript=d / "transcript.json",
                          descriptions=d / "descriptions.json")
told = video.excerpt(transcript=True, answers={"clip": ["summary"]})
aggregates.summary(input=told, out=d / "answers" / "summary.json", llm=models.llm)
aggregates.chapters(input=told, out=d / "answers" / "chapters.json",
                    llm=models.llm, embedder=models.embedder)

print(aggregates.load(d / "answers" / "summary.json").payload["summary"])
for c in aggregates.load(d / "answers" / "chapters.json").payload["chapters"]:
    print(f"{c['start_ts']:.0f}s", c["title"])

The output is in data/out/shop/: one JSON file per stage and the kept frames in store/ (what each file holds). Recipes has longer scripts.
