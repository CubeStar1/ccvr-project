Concepts

The terms the rest of these pages use.

Two tiers

video_rag reads the video in eight stages, ending with every chunk described and embedded, and provides search.

aggregates reads the files video_rag wrote, never the video, and answers questions about the whole video: counts, summaries, chapters, people.

workflow runs both in one call.

The chunk grid

A video is cut into chunks: consecutive spans, typically 5 to 30 seconds, stored in timeline.json. Every later file, from frames to vectors, is keyed by chunk_id, so chunk 7 covers the same seconds in all of them. Search returns chunks.

The policy decides where the boundaries fall:

PolicyCuts atNeeds
uniformevery chunk_s seconds (default 20)nothing
scenecuts in the picturea scene-detection pass
vadpauses in speechthe transcript
speakerchanges of speakerthe transcript, with speakers

Chunks are kept between min_s and max_s long: short ones are merged and long ones split evenly (see boundaries).

The video's folder

Each video gets its own folder, <into>/<video_id>/, with one file per stage:

The fields of each file are listed in the Reference.

Video ids

The video id is the folder name, by default the filename without its extension (shop.mp4 becomes shop). It may contain ASCII letters, digits, -, _ and ., and may not start with _; for other filenames, pass video_id=.

Running the same file again reuses its folder. If a different file has the id, the run gets a new one such as shop-2, unless on_conflict is "replace" (delete the old folder) or "refuse" (raise). run.video_id holds the id used.

Frames, samplers and questions

The video is decoded once and frames are offered at per_second (default 1). A sampler decides which to keep: uniform every Nth frame, and clip, yolo, objects and text a frame where the scene, people, objects or on-screen text change. See Samplers.

A question is what the vision model is asked about the kept frames, with the fields its answer must fill. Each sampler has a default question, and its prompts pair it with any other. See Questions.

Answer ids

Each answer is stored under an answer id made from the sampler and the question:

SamplerAnswer ids
Clip()clip (its own question)
Uniform(prompts=["text"])uniform:text
Clip(prompts=["text", "scene"])clip:text, clip:scene, from one pass
Clip(prompts=["clip", "checkout"])clip, clip:checkout, from one pass

A chunk's transcript has the id transcript. Search filters and aggregate inputs refer to answers by these ids.

Units and vector spaces

A unit is one embedded piece of text: one answer for one chunk, or one chunk's transcript. embedded.json holds every unit with its vector.

Each vector is tagged with its embedder's key, such as local:BAAI/bge-small-en-v1.5:384, and vectors with different keys are never compared. Search with the embedder that built the index.

Reuse

Expensive work is reused while its inputs are unchanged:

  • a description: the frames, the vision model and its settings, and the question's wording;
  • a vector: its text and the embedder;
  • an aggregate answer: the text it reads, its definition and the model.

The pipelines do this automatically. When you call a stage or aggregator yourself, pass the earlier output as previous=.

Model keys

Every model has a key, such as openai:gpt-6-luna, which is stored with each answer and vector and decides reuse. In your own model class, change the key whenever the model changes, or the old model's answers are reused. See Models.

Files and databases

Every stage writes a file. With a database, the pipeline also sends each new document to it; a failed write is recorded in run.problems and the run continues. Search reads from a database, and Folder reads the output folder directly, so no server is needed. See Databases.

Errors

Every error VIDRA raises deliberately is a vidra.VidraError. vidra.Unavailable means something is missing (a package, weights, a key or a server) and Refused, also a ValueError, means the request is invalid. Most are raised before any work starts. See the full list.
