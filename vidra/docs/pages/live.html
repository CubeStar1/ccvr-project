Live streams

Describe a live stream as it plays. Each frame a sampler keeps is sent to the vision model as soon as it arrives.

Running one

from vidra import LocalEmbedder, Models, OpenAI
from vidra.video_rag import video_rag_live
from vidra.video_rag.samplers import Clip

def check(o):                                   # every answer, as it is ready
    if o.structured.get("rule") == "no_hard_hat":
        print(f"{o.seen_at}  chunk {o.chunk_id}  t={o.media_ts:.1f}s  {o.description}")

run = video_rag_live("tcp://0.0.0.0:9000?listen=1", "data/out", video_id="dock-3",
                     sampler=Clip(prompts=["safety"]), on_unit=check,
                     models=Models(vlm=OpenAI(), embedder=LocalEmbedder()))
print(run.observations, "answers,", run.dropped, "dropped, lag", run.lag_s)

The call blocks until the stream ends. on_unit is called with each answer as soon as it is ready, and your code decides what counts as an event. To detect a condition, check a one_of field rather than comparing vectors: embeddings handle negation poorly, so "wearing a hard hat" and "without a hard hat" end up close together.

Testing with a file

live.send streams a file to a port in real time, so you can test without a camera. The receiver loads its models before it starts listening, which can take half a minute, so the sender retries for up to connect_timeout_s.

import multiprocessing
from vidra.video_rag import live, video_rag_live

if __name__ == "__main__":
    sender = multiprocessing.Process(target=live.send,
                                     args=("shop.mp4", "tcp://127.0.0.1:9000"),
                                     kwargs={"speed": 1.0})
    sender.start()
    run = video_rag_live("tcp://127.0.0.1:9000?listen=1", "data/out", video_id="shop-live")
    sender.join()

Run the sender in a separate process, as above. While it waits to connect, PyAV holds the GIL, so a sender on a thread in the same process slows the receiver down.

send(path, url, speed=1.0, connect_timeout_s=120.0, format=None) sends the video without re-encoding it: as MPEG-TS for H.264, HEVC and MPEG-2/4, and as Matroska for other codecs such as VP9 and AV1. Pass format= to choose the container. Codecs PyAV cannot write, such as Theora, are refused, so re-encode those files first. The live recipe is a complete script.

The source can be any URL PyAV opens (tcp://host:port?listen=1, udp://, rtmp://, rtsp://; not SRT), or a file, read as fast as it decodes, which keeps the frames video_rag keeps under the uniform policy.

Frames only

live.frames reads a stream's frames the same way video_rag_live does, but without samplers or model calls. Use it to run your own model, such as a person tracker, on a stream:

live.frames(url, per_second=None, open_timeout_s=60.0, read_timeout_s=10.0, gap_s=2.0) -> Iterator[tuple[Frame, Arrival]]
from vidra.video_rag import live

for frame, arrival in live.frames("rtsp://camera-2/stream", per_second=5):
    tracks = tracker.update(frame.image)       # BGR pixels
    log(arrival.seen_at, frame.media_ts, tracks)

Each frame is a video.Frame whose media_ts counts from the first frame. Each live.Arrival has seen (time.perf_counter() at decode), seen_at (UTC, ISO 8601) and gap_before, which is true when the clock jumped by more than gap_s just before the frame. Packets the decoder rejects are skipped.

The stream is opened when the first frame is requested and closed when the loop exits, including on break. Iteration stops when the sender disconnects or nothing arrives for read_timeout_s.

What each answer carries

ObservationIs
chunk_id, media_ts, frame_indexWhere the kept frame is.
sampler_id, sampler, questionWhich answer this is, as in video_rag.
frames, frame_tsEvery frame the model was shown, in time order, each once: views made from a frame are not listed.
description, structuredThe answer.
content, vectorWhat was embedded, and its vector.
seen_at, answered_at, lag_sWhen the frame arrived and when its answer was ready (UTC), and the seconds between.
gap_beforeThe stream's clock jumped just before this frame.

Each observation is also appended to observations.jsonl in the run's folder.

Context frames

A single frame can't show movement. context=(1, 0) sends the previous decimated frame too; (0, 1) the next one; (1, 1) both. A frame after the kept one delays its answer by one decimation interval (1 s at per_second=1); frames before cost nothing but tokens.

When the model falls behind

If frames are kept faster than the model answers them, the oldest waiting frame is dropped and counted in run.dropped, so the lag does not keep growing. To keep up, raise the model's concurrency, keep fewer frames with the sampler's min_interval_s or max_per_chunk, or lower per_second.

When the stream ends

The run is written as media.json, timeline.json, manifest.json, descriptions.json and embedded.json, so search and aggregates read it like any other video. In descriptions.json, each chunk's description joins its frames' answers in time order, and the individual answers are kept under observations.

LiveRunIs
endedended, stopped, stop_after_s or error.
observations, failed, droppedAnswers written, model calls that failed (the run goes on), frames dropped from the queue.
written, unwrittenAnswers that reached database as they arrived, and those that did not.
lag_sSeconds from arrival to answer: p50, p95, max.
gapsWhere the stream's clock jumped.
duration_s, chunks, frames_decimated, frames_sampledHow much was read.
recording, steps, problemsThe recording's path, the documents written, and what failed.

An exception from on_unit, other than StopStream, stops the run and is re-raised after the documents are written.

Writing to a database as it runs

from datetime import datetime, timedelta, timezone
from vidra import LocalEmbedder, Models, Supabase
from vidra.video_rag import search_observations, video_rag_live
from vidra.video_rag.samplers import Clip

db = Supabase()
models = Models(embedder=LocalEmbedder())
run = video_rag_live("rtsp://dock-3.local/stream", "data/out", video_id="dock-3",
                     sampler=Clip(prompts=["safety"]), models=models, database=db)

# from anywhere, while it runs: the last ten minutes on dock-3
hits = search_observations("liquid spilled on the floor", "dock-3",
                           since=datetime.now(timezone.utc) - timedelta(minutes=10),
                           models=models, database=db)
for h in hits:
    print(h.seen_at, h.media_ts, h.frame_index, h.description)

With database=, each answer is written as it arrives through write_observations, with any backlog sent in one call; the other documents follow when the stream ends, so search finds the run by chunk too. A failed write is counted in run.unwritten; every answer is still in observations.jsonl.

Logging important moments

To flag moments as they happen, such as a worker without a hard hat or a spill, subclass your database and check each answer in write_observations before storing it.

The hook runs on the writer thread, so slow checks don't delay answers. An exception in it is counted in run.unwritten, so catch your own errors, as the example does, to keep the answers stored. Runs sharing one database call the hook concurrently; guard shared state with a lock.

The example checks answers in two ways:

  • Rules are exact matches on one_of fields, such as row["structured"]["hard_hats"] == "a member of staff without one". Give each rule its own field and include a "cannot tell" option; without one, the model guesses. Only ask about what the camera can actually resolve.
  • Other hazards are matched by similarity, comparing your description with each hazard the answer lists rather than with the whole answer. A whole answer describes everything in view, so a single detail barely changes its vector. The example uses a threshold of 0.85 with LocalEmbedder; measure your own for your embedder and footage.

Flags are only as good as the vision model's judgement, and some will be wrong. Treat a flagged moment as something to review.

docs/pages/examples/live_moments.py
"""Log the moments a live stream shows that match ones you describe, as they
arrive: a Supabase subclass that looks at each answer before storing it.

    python live_moments.py rtsp://camera/stream     # or a file, read as a stream
"""

import json
import sys
import threading

import numpy as np

import vidra
from vidra import LocalEmbedder, Models, OpenAI, Supabase
from vidra.video_rag import describe, video_rag_live
from vidra.video_rag.samplers import Clip

vidra.configure(env_file=".env")

# A question whose answers are easy to check: one fixed-choice field per rule,
# each with a way to say "cannot tell" (without one, the model guesses), and a
# list of hazards, each a short phrase, for everything else.
SEEN = ["every member of staff wears one", "a member of staff without one",
        "cannot tell", "no staff visible"]
describe.add_question(
    "ppe",
    "These {n} frames span {span}. Describe the staff at work (not customers or "
    "visitors) and any safety hazards.",
    fields={
        "hard_hats": {"type": "text", "about": "hard hats on the staff", "one_of": SEEN},
        "hi_vis": {"type": "text", "about": "high-visibility vests or clothing on "
                   "the staff", "one_of": SEEN},
        "hazards": {"type": "list", "about": "each hazard visible, in a few words"},
    },
)
RULES = {"hard_hats": "no hard hat", "hi_vis": "no high-visibility clothing"}

# What to look for among the hazards, matched by similarity.
TARGETS = {"spill": "liquid spilled on the floor",
           "blocked_exit": "boxes or a pallet blocking a doorway",
           "ladder": "a person working on a step ladder"}


class Moments(Supabase):
    """Supabase, plus: every answer that breaks a rule or names a hazard close to
    a target is logged as a moment before it is stored."""

    def __init__(self, targets, embedder, threshold=0.85, log="moments.jsonl", **kwargs):
        super().__init__(**kwargs)
        self.embedder = embedder
        self.names, self.targets = list(targets), self._unit(list(targets.values()))
        self.threshold, self.log = threshold, log
        self.lock, self.found = threading.Lock(), 0

    def _unit(self, texts):
        vectors = np.array(self.embedder.embed(texts))
        return vectors / np.linalg.norm(vectors, axis=1, keepdims=True)

    def write_observations(self, video_id, rows):
        try:
            self.record([m for row in rows for m in self.matches(video_id, row)])
        except Exception as exc:         # a bug here must not stop the storing
            print("matching failed:", exc)
        super().write_observations(video_id, rows)

    def matches(self, video_id, row):
        moment = {"video_id": video_id, "frame_index": row["frame_index"],
                  "media_ts": row["media_ts"], "seen_at": row["seen_at"],
                  "description": row["description"]}
        for field, target in RULES.items():
            if row["structured"].get(field) == "a member of staff without one":
                yield {**moment, "target": target, "matched": field, "similarity": None}
        # Each hazard on its own: a whole answer is a paragraph about everything
        # in shot, and one detail in it barely moves its vector.
        hazards = row["structured"].get("hazards") or []
        if hazards:
            similar = self._unit(hazards) @ self.targets.T          # hazards x targets
            for h, t in zip(*np.nonzero(similar >= self.threshold)):
                yield {**moment, "target": self.names[t], "matched": hazards[h],
                       "similarity": round(float(similar[h, t]), 3)}

    def record(self, moments):
        # Several runs may share one database, each writing from its own thread.
        with self.lock, open(self.log, "a", encoding="utf-8") as out:
            for m in moments:
                out.write(json.dumps(m) + "\n")
                print(f"{m['seen_at']}  {m['video_id']}  t={m['media_ts']:.1f}s  "
                      f"{m['target']}: {m['matched']}")
            self.found += len(moments)


embedder = LocalEmbedder()
database = Moments(TARGETS, embedder)
run = video_rag_live(sys.argv[1], "data/out", sampler=Clip(prompts=["ppe"]), context=(1, 0),
                     models=Models(vlm=OpenAI("gpt-6-luna"), embedder=embedder),
                     database=database)
print(f"{run.observations} answers, {database.found} moments, "
      f"{run.written} stored as they arrived, lag {run.lag_s}")

To keep the moments in Supabase instead of a file, create a table and insert into it from record:

create table if not exists vidra.moments (
  video_id text, frame_index bigint, media_ts double precision, seen_at timestamptz,
  target text, matched text, similarity real, description text,
  primary key (video_id, frame_index, target, matched)
);
    def record(self, moments):
        if moments:
            self.writer().table("moments").upsert(moments).execute()

To run without a server, subclass Folder or Database instead of Supabase. Moments can be sent anywhere else, such as a webhook or a queue, in the same way.

Differences from video_rag

  • The soundtrack is not transcribed, because speakers can only be identified from the whole recording. Set record=True and run video_rag on the recording afterwards.
  • Chunks are always uniform, and a short final chunk is not merged into the one before.
  • Time starts at the first frame. A jump forward of more than 2 s is recorded as a gap; after a jump backward, such as a reconnect, the clock continues from where it was.
  • Damaged packets are skipped and counted in the manifest instead of stopping the run.
