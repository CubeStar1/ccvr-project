Custom prompts and profiles

Your own aggregators: a prompt asks the LLM about the whole video; a linking profile follows one kind of thing across chunks.

The built-in summary, chapters and events aggregators are prompts, and entities:people, entities:objects and entities:text are profiles. The ones you add are saved in aggregates.json under the data root and run in the same way.

Prompts

aggregates.add_prompt(name, instruction, fields, *, kind="fold", key=None, fold_instruction=None, about="") -> dict

    fields={

        "severity": {"type": "text", "about": "how serious it was",
                     "one_of": ["none", "minor", "major"]},
    },
    kind="fold",
)

ArgumentMeaning
nameLowercase letters, digits, _, -, starting with a letter. Not a built-in, stats, speakers, coverage, ner, sentiment or entities.
instructionWhat the LLM is told. The chunks' text follows it, each tagged with its chunk id.
fieldsThe answer's fields, as for questions: type, about, one_of, of (fields).
kindfold, spans or items (below).

fold_instructionFor fold: the instruction for summarising each intermediate group.

Returns the stored definition. Adding a prompt under an existing name replaces it.

The three kinds

KindAnswersHowLike
foldone answer for the whole videoChunks are summarised in groups, then the summaries are summarised, until one remains. Handles any length.summary
spansa list of consecutive parts, each filling fields, with chunk_ids, start_ts, end_tsThe embedder places boundaries; the LLM fills each part's fields. Takes max_spans, min_span_s and an embedder.chapters

Running a prompt

  • Call aggregates.custom(name=..., input=..., out=..., llm=...).
  • Pass it as a keyword argument to aggregates.aggregate: aggregate(out=..., incident_report=seen).
  • workflow with tier="llm" runs every added prompt.

Editing a prompt recomputes its answers on the next run.

Linking profiles

A profile links the entries of one list field across chunks, such as each person in people, into entities, and the LLM then writes an account of each entity. The linking itself uses embeddings, not the LLM.

aggregates.add_profile(name, field, instruction, fields, *, identity=None, story=None, transcript=None, threshold=None, rule=None, mutual=None, check=None, min_appearances=None, max_narratives=None, weights=None, attributes=None, near=None, shared=None, about="") -> dict
aggregates.add_profile(
    "tools", "objects",
    "These may be the same object, seen in different chunks. Say what it is and who used it.",
    fields={"use": {"type": "text", "about": "who used it, and for what"}},
    identity=["object", "appearance"],
    story=["context"],
)

tools = video.sightings(profile="tools", answers=["objects"])
aggregates.entities(profile="tools", input=tools, out=D / "answers" / "tools.json",
                    llm=models.llm, embedder=models.embedder)   # answer id: entities:tools
ArgumentDefaultMeaning
namerequiredRuns as entities:<name>.
fieldrequiredThe list field to link, e.g. people, objects, or one of your question's.
instructionrequiredThe account instruction; numbered observations follow in time order.
fieldsrequiredThe account's fields.
identity[]Keys that identify an entry (["appearance", "clothing"]). Without them the whole entry is compared and threshold is required.
story[]Extra keys the account reads (["role", "action"]).
transcriptFalseAlso give the account the transcript of the entity's chunks.
thresholdread off the videoA fixed cosine similarity (0 to 1) above which entries are linked. Required without identity; not allowed with weights or attributes.
rule"max"How the threshold is set from pairs known to be different (two entries in one answer). "max" sets it above the most similar such pair; "q95" sets it above the 95th percentile, which links more.
mutualTrueLink only mutual best matches.
check"flag""flag": the LLM marks contradicting observations as doubts. "off": no check.
min_appearances2Minimum sightings for an account.
max_narratives12Maximum accounts (up to 50).
weightsnone{identity key: weight}: embed each key separately and weight them.
attributesnone{key: weight} for fixed-vocabulary keys (gender, top_color) whose agreement also counts.
nearnoneAttribute values that count as nearly equal: [["dark_blue", "black"], ["jacket", "coat"]].
sharednone{key: weight}: credit for shared accessories or distinguishing words.
about""One-line description.

The built-in people profile uses weights, attributes, near, shared and rule="q95"; objects and text use one embedding and rule="max". aggregates.definition("entities:people") shows a profile's full definition.

In aggregate(...), write the colon as an underscore: entities_tools=tools.

Listing and removing

aggregates.definition("incident_report")     # the stored entry, with "name", "kind", "builtin"
aggregates.definition("entities:people")     # a profile; its kind is "link"
aggregates.available()                       # every aggregator id, yours included
aggregates.remove_prompt("incident_report")  # answers already written are kept
aggregates.remove_profile("tools")

Changing a built-in raises aggregates.ProtectedDefinition. Invalid definitions raise aggregates.DefinitionError when added; .problems lists each issue.

Complete example

docs/pages/examples/custom_aggregate.py
"""Aggregators of your own: a prompt run over the whole video, and a linking
profile that follows one kind of thing across chunks.

    python custom_aggregate.py data/out/<video_id>
"""

import sys
from pathlib import Path

import vidra
from vidra import LocalEmbedder, Models, OpenAI, aggregates

vidra.configure(env_file=".env")
D = Path(sys.argv[1])
models = Models(llm=OpenAI("gpt-6-luna"), embedder=LocalEmbedder())
video = aggregates.record(timeline=D / "timeline.json",
                          transcript=D / "transcript.json",
                          descriptions=D / "descriptions.json")
told = video.excerpt(transcript=True, answers={"clip": ["summary"]})

# fold: one answer over the whole video.
aggregates.add_prompt(
    "incident_report",
    "Write an incident report for this video.",
    fields={
        "report": {"type": "text", "about": "what happened, in order"},
        "severity": {"type": "text", "about": "how serious it was",
                     "one_of": ["none", "minor", "major"]},
        "people_involved": {"type": "list", "about": "each person involved, by appearance"},
    },
    kind="fold",
    about="an incident report with a severity",
)

# items: discrete things, each citing the chunk it is in.
aggregates.add_prompt(
    "handovers",
    "List every moment something is handed from one person to another.",
    fields={
        "what": {"type": "text", "about": "what was handed over"},
        "between": {"type": "text", "about": "who gave it to whom, by appearance"},
    },
    kind="items",
    key="handovers",
)

aggregates.custom(name="incident_report", input=told,
                  out=D / "answers" / "incident_report.json", llm=models.llm)
report = aggregates.load(D / "answers" / "incident_report.json").payload
print(report["severity"], "-", report["report"][:200])

# Linking: the same object across chunks, from the `objects` field of the
# `objects` sampler's answers (video_rag with sampler=Objects(...)).
aggregates.add_profile(
    "tools", "objects",
    "These may be the same object, seen in different chunks. Say what it is "
    "and who used it for what.",
    fields={"use": {"type": "text", "about": "who used it, and for what"}},
    identity=["object", "appearance"],     # what decides that two entries are one
    story=["context"],                     # what the account reads besides
)

# All of them run in the pipeline too, each a keyword named after it
# (`entities:tools` is spelled `entities_tools`).
inputs = {"incident_report": told, "handovers": told}
if "objects" in video.answer_ids():
    inputs["entities_tools"] = video.sightings(profile="tools", answers=["objects"])
done = aggregates.aggregate(out=D / "aggregates", previous=D / "aggregates",
                            models=models, **inputs)
print("wrote:", sorted(done.artifacts))
print(aggregates.definition("handovers"))
