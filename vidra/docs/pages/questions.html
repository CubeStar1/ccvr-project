Questions

What the vision model is asked about each chunk, and how to add your own questions.

What a question is

For each chunk, describe sends the kept frames with:

  • An instruction, such as "These 4 frames span 0:20–0:40 and were kept because the people in shot changed..."
  • A shape: the fields the answer must fill, sent as a JSON Schema. Every answer also includes a prose summary, which is the main text that gets embedded.

Each answer is stored under its answer id, with the prose in description and the fields in structured. Both are embedded, and search can filter on fields. Clip() asks clip's own question, stored as clip; Clip(prompts=["checkout"]) asks checkout, stored as clip:checkout (answer ids).

Built-in questions

QuestionAsksShape
scenethe segment as a whole: where, who and what, what happens, what changesscene
uniformthe same, for evenly spaced framesscene
clipthe same, then what changed from frame to framescene
yoloone entry per distinct personpeople
objectsone entry per distinct object, told what the detector looked forobjects
texteach piece of text, transcribed exactlytext
overviewwhat is happening, in 4 to 5 sentences; no fieldsprose

Shapes

ShapeFields
scenesetting; lists people (by appearance), objects, visible_text, actions, changes, tags. The fallback for questions without a shape.
peoplepeople: one object per person with appearance, clothing, role, action, and fixed-vocabulary gender, age_group, hair_color, hair_style, top_color, top_type, bottom_color, bottom_type, accessories, distinguishing
objectsobjects: one object per thing, with object, appearance, context
textvisible_text: one object per piece of text, with text, context
prosenone: a 4 to 5 sentence summary

Every shape except prose asks for a summary of at least 150 words. Structured answers are long, and a reasoning model's reasoning counts against max_output_tokens, which is why it defaults to 8000.

Adding a question

describe.add_question(name, instruction, *, fields=None, shape=None, summary=None, about="") -> dict
from vidra.video_rag import describe

describe.add_question(
    "hazards",
    "These {n} frames span {span}. List every safety hazard you can see.",
    fields={
        "hazards":  {"type": "list", "about": "each hazard, briefly"},
        "severity": {"type": "text", "about": "the worst one",
                     "one_of": ["none", "low", "high"]},
        "exposed":  {"type": "list", "about": "who is at risk",
                     "of": {"who": "by appearance", "how": "how they are exposed"}},
    },
    about="safety hazards and who is exposed",
)

video_rag("site.mp4", "data/out", sampler=Clip(prompts=["clip", "hazards"]), models=models)
ArgumentMeaning
nameLowercase letters, digits, _, -; starts with a letter; up to 32 characters; not a built-in.
instructionWhat the model is told. May use {n} (frame count), {span} (the chunk's time span) and {vocabulary} (the objects vocabulary).
fieldsThe answer's own fields (below).
shapeInstead of fields, a built-in shape: scene, people, objects, text or prose.
summaryWith fields: prose length, "standard" (150+ words, default) or "brief" (4 to 5 sentences).
aboutOne-line description.

With neither fields nor shape, the answer is prose only. Adding a question under an existing custom name replaces it. The return value is question(name).

The fields

Each field is a dict:

KeyMeaning
type"text" (a string) or "list".
aboutRequired. What goes in the field.
one_ofThe allowed values. Use it for any field you will filter on, because free text varies (cashier, cashier or customer).
ofFor a list, make each entry an object with these keys, {key: what goes there}, so related details stay together.

Field names use lowercase letters, digits and _, starting with a letter. Limits: 12 fields, 8 keys per of, 24 values per one_of. Invalid questions are refused when added.

Listing and removing

describe.questions()                # every question name, built in or added
describe.question("hazards")        # {"name", "instruction", "about", "builtin",
                                    #  "shape", "summary", "fields": {field: about}}
describe.remove_question("hazards") # answers already stored are kept
  • Questions are saved in prompts.json under the data root. You can edit the file by hand; a malformed entry is skipped with a warning.
  • Changing a built-in question raises describe.ProtectedPrompt. Other problems raise describe.PromptError, which lists each one.
  • A run that names a removed question is refused.

Searching by a question

from vidra.video_rag import search

moments, notes = search("someone near the edge", "site", question="hazards",
                        structured={"severity": "high"}, models=models, database=db)
moments[0].hits[0]["structured"]    # {"hazards": [...], "severity": "high", "exposed": [...]}

question= limits the search to that question's answers, from any sampler. structured= keeps answers whose field equals the value, or whose list field contains it. See Search.

Editing a question

Editing a question re-describes only its answers, and adding one changes nothing stored. Changing the vision model or max_output_tokens re-describes everything.

Complete example

docs/pages/examples/custom_question.py
"""A question of your own: what the vision model is asked about each chunk,
and the fields its answer must fill. Then search by those fields.

    python custom_question.py path/to/video.mp4
"""

import sys

import vidra
from vidra import Folder, LocalEmbedder, Models, OpenAI
from vidra.video_rag import describe, search, video_rag
from vidra.video_rag.samplers import Clip

vidra.configure(env_file=".env")
source = sys.argv[1]
models = Models(vlm=OpenAI("gpt-6-luna"), embedder=LocalEmbedder())
database = Folder("data/out")

# Saved in data/prompts.json; adding it again replaces it.
describe.add_question(
    "checkout",
    "These {n} frames span {span}. Describe what happens at the checkout.",
    fields={
        "payment": {"type": "text", "about": "how the customer pays, if it can be seen",
                    "one_of": ["cash", "card", "phone", "none visible"]},
        "items": {"type": "list", "about": "each item scanned, bagged or handed over"},
        "people": {"type": "list", "about": "each person at the checkout",
                   "of": {"role": "cashier, customer or bystander",
                          "doing": "what their hands are doing"}},
    },
    about="the checkout: payment, items, who does what",
)
print(describe.question("checkout")["fields"])

# clip's frames, asked clip's own question and ours, in one decode.
run = video_rag(source, "data/out", policy="scene", sampler=Clip(prompts=["clip", "checkout"]),
                models=models, database=database)

# Only answers to our question, and only those that saw cash.
moments, notes = search("a customer paying", run.video_id, question="checkout",
                        structured={"payment": "cash"},
                        models=models, database=database)
for m in moments:
    answer = m.hits[0]["structured"]
    print(f"{m.start_ts:6.1f}-{m.end_ts:6.1f}s  payment={answer['payment']}  "
          f"items={answer['items'][:3]}")
for note in notes:
    print("note:", note)
