Samplers

Which frames of each chunk are kept and sent to the vision model.

How sampling works

  1. The video is decoded once, however many samplers run.
  2. Frames are offered at per_second (default 1), by media time, so variable frame rates are handled.
  3. Each sampler keeps the offered frames its rule selects, and always the first frame of each chunk.
  4. min_interval_s and max_per_chunk are checked first, so frames they exclude cost no model time.
  5. Samplers reset at each chunk boundary.
  6. Kept frames are saved once to store/ and listed in manifest.json.

A sampler is an object. Pass one, or a list, as the sampler argument of video_rag, video.video or video_rag_live; the default is Uniform().

from vidra.video_rag import video_rag
from vidra.video_rag.samplers import Clip, Yolo

video_rag("shop.mp4", "data/out", sampler=[Clip(), Yolo()])

Each class has a lowercase name, which is what its answers are stored under: uniform, clip, yolo, objects and text. A model-backed sampler loads its model when a run first uses it, so making one is instant.

Uniform

Keeps every every_n-th offered frame, counted from each chunk's start. No model. At per_second=1, every_n=5 is one frame every 5 s; for a fixed interval in seconds use min_interval_s.

Use it for even coverage, or to ask a question at regular intervals: Uniform(every_n=5, prompts=["text"]) reads the screen every 5 s without running a text detector.

SettingDefault
every_n1: every offered frame

Clip

Embeds each frame with CLIP (openai/clip-vit-base-patch32) and keeps it when its similarity to the last kept frame drops below threshold, so a slow pan triggers once it has moved far enough. A good default for most footage.

SettingDefaultEffect
threshold0.96Lower keeps fewer frames.

Yolo

Finds people with YOLO (yolo11n.pt), embeds each person's crop with CLIP, and keeps the frame when someone in view no longer matches anyone in the last kept frame. People leaving don't trigger it. In crowded scenes it triggers often, so combine it with min_interval_s.

Its question returns one entry per person: appearance, clothing, role, action and fixed-vocabulary attributes (gender, age group, hair, top and bottom colour and type, accessories). entities:people links these across chunks.

SettingDefaultEffect
threshold0.83Lower keeps fewer frames.

Objects

Detects the objects in vocabulary with YOLO-World (yolov8s-worldv2.pt) and keeps the frame when detections no longer match the last kept frame's by class and position. Its question is told the vocabulary and returns one entry per object (object, appearance, context).

SettingDefaultEffect
vocabularyshopping bag, plastic bag, shopping cart, shopping basket, cardboard box, bottle, grocery item, cash registerWhat to detect. Set this to match your footage; a list that doesn't fit finds fewer objects and mislabels them.
confidence0.30Minimum detection confidence.
threshold0.30Lower keeps fewer frames.

Text

Locates text with OpenCV's PP-OCRv3 detector and keeps a frame when the text layout changes; its question has the vision model transcribe the text. For slides, screen recordings and signs. It needs no PyTorch: the 2.4 MB model runs on the CPU, about 0.2 s per 720p frame, and is downloaded on first use.

SettingDefaultEffect
threshold0.92Lower keeps fewer frames.

Configuring samplers

Every class also takes min_interval_s, max_per_chunk and prompts. The same list works for video.video, video_rag and video_rag_live.

from vidra.video_rag import video_rag
from vidra.video_rag.samplers import Clip, Objects, Yolo

video_rag("x.mp4", "data/out",
          sampler=[Clip(threshold=0.93, prompts=["safety"]),
                   Objects(vocabulary=["forklift", "pallet"], confidence=0.4),
                   Yolo(min_interval_s=2)])

Each run uses its own copy of the object, so one object can serve several runs, and a model it loaded is loaded once. A list may contain each sampler once; put all of a sampler's questions on its object.

Crops

yolo and objects can send the vision model enlarged crops of the largest detections in each kept frame, with the frame or instead of it. The crops reuse the sampler's detections, but each adds an image to the model call. Enlarging adds no detail; it keeps small subjects from shrinking further when the model's API downscales the image.

SettingDefaultEffect
send"frame"What the model is shown for a kept frame: "frame" the frame alone, "both" the frame then its crops, "crops" the crops alone. A kept frame with nothing detected is shown as itself.
crops3At most this many detections, the largest, ordered left to right.
crop_sizenoneEnlarge a crop until its shorter side is this many pixels, at most 4 times; never shrink. None keeps the size it was cut at.
crop_margin0.1Context around each box, as a fraction of its width and height.
video_rag("site.mp4", "data/out",
          sampler=Yolo(send="both", crops=3, crop_size=512))

With "both", each frame is followed by its crops, labelled like "Frame 2, person 1 of 3 from the left, enlarged 3.1x". "crops" is cheaper but loses each subject's surroundings. Each crop's box, class, confidence and scale are recorded in the manifest. (yolo's crop_pad is unrelated: it pads the crops CLIP compares to decide what to keep.) Your own samplers can send any images they make; see views.

Choosing a threshold

The same threshold keeps very different numbers of frames on different videos: a clip threshold that keeps a fifth of a quiet camera's frames can keep over half of a busy one's. To control cost, set min_interval_s or max_per_chunk rather than the threshold; they spread the kept frames evenly across chunks.

Questions and answer ids

prompts lists the questions asked about the frames a sampler keeps. Without it, a sampler asks its own question, the one named after it. Each answer is stored under an id made of the sampler's name and the question:

SamplerMeansAnswer ids
Clip()clip's frames, clip's own questionclip
Uniform(prompts=["text"])every Nth frame, asked to read the screenuniform:text
Yolo(prompts=["overview"])frames where people changed, as short proseyolo:overview
Clip(prompts=["text", "scene"])one pass, two questionsclip:text, clip:scene
[Clip(), Yolo()]two samplers, one decodeclip, yolo
Clip(prompts=["clip", "checkout"])one clip pass, its own question and checkoutclip, clip:checkout
  • Each question costs one model call per chunk.
  • Each question must be built in or added; unknown questions are refused before decoding starts.
  • Search filters and aggregate inputs use the answer ids: search(..., sampler="clip:text").

Writing your own

To use your own rule for keeping frames, subclass Sampler and implement propose. See Custom samplers.

Processing times for each sampler, on a GPU and on the CPU, are in Hardware.
