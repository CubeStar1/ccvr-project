Aggregates

Whole-video answers: counts, speakers, summaries, chapters, events, recurring people and objects.

From files to an answer

files ──► record ──► input ──► aggregator ──► answer file (what exists) (what to read) (what to ask)
  1. A record is the set of a video's output files.
  2. An input is the text one aggregator reads, built from the record. Nothing is included by default; you choose the transcript, answers and fields.
  3. An aggregator reads one input and writes one answer file.
from pathlib import Path
from vidra import LocalEmbedder, Models, OpenAI, aggregates

models = Models(llm=OpenAI("gpt-6-luna"), embedder=LocalEmbedder())
D = Path("data/out/shop")                                   # a folder video_rag wrote

video = aggregates.record(timeline=D / "timeline.json", transcript=D / "transcript.json",
                          descriptions=D / "descriptions.json")
told = video.excerpt(transcript=True, answers={"clip": ["summary"]})
aggregates.summary(input=told, out=D / "answers" / "summary.json", llm=models.llm)

print(aggregates.load(D / "answers" / "summary.json").payload["summary"])

Aggregates never open the video and don't need a database. The aggregates recipe is a complete script.

Records

aggregates.record(*, timeline, transcript=None, descriptions=None, manifest=None) -> Record
ArgumentMeaning
timelineRequired: timeline.json.
transcripttranscript.json, for anything that reads speech.
descriptionsdescriptions.json, for anything that reads the answers.
manifestmanifest.json; only stats reads it (frames counted).

Files from different videos or grids are refused with aggregates.RecordError. A Record has .video_id, .timeline and three methods:

video.answer_ids()       # ["clip", "clip:checkout", "yolo"]: the answers it holds

excerpt: text per chunk

Record.excerpt(*, transcript=False, answers=None, out=None) -> Excerpt

Builds the per-chunk text that text aggregators read: the transcript if transcript=True, and the listed fields of each named answer. "summary" means the answer's prose; other names are fields.

said = video.excerpt(transcript=True)
seen = video.excerpt(answers={"clip": ["summary"],
                              "clip:checkout": ["summary", "payment", "items"]})
both = video.excerpt(transcript=True, answers={"clip": ["summary", "actions"]})

Answer ids must match exactly. An unknown answer or field is refused, and the error lists what the record holds. Chunks with no selected text are left out.

sightings: entries to link

Record.sightings(*, profile, answers=None, keys=None, out=None) -> Sightings

Builds the input for a linking profile: every entry of the profile's list field in the named answers. For people, each person in each yolo answer is one sighting.

people = video.sightings(profile="people", answers=["yolo"])
by_clothes = video.sightings(profile="people", answers=["yolo"], keys=["clothing"])

keys limits linking to some of the profile's identity keys; it can't add new ones.

Saving inputs

With out=, the input is also written to a file. Aggregators accept that path in place of the object, and aggregates.load_input(path) reads it back.

video.excerpt(transcript=True, out=D / "inputs" / "said.json")
aggregates.summary(input=D / "inputs" / "said.json", out=D / "summary.json", llm=models.llm)

The aggregators

Tiers are costs: free aggregators count, local ones run a small local model (vidra[local]), and llm ones call the LLM.

AggregatorTierReadsAnswers
statsfreerecordduration, chunk lengths, words, words per minute, frames and answers counted
coveragefreerecordhow many chunks have picture, sound, both or neither
speakersfreerecord with a transcriptspeakers, turns, handovers, speech ratio, the dominant speaker
nerlocalexcerptnamed entities (GLiNER) and the chunks each appears in
sentimentlocalexcerpttone per chunk (DistilBERT), overall, and where it turns
summaryllmexcerpta summary, topics, setting, notable moments
chaptersllmexcerptconsecutive chapters with titles, summaries and times
eventsllmexcerptdiscrete events, each tied to a chunk
entitiesllmsightingsthe same person, object or text linked across chunks, with an account of each
customllmexcerpta prompt of your own (Custom prompts)

Each writes one answer to out and returns a receipt. All take previous=, an earlier answer reused if still current; LLM aggregators take llm=, and embedder= if they use one. Only aggregate() takes a Models. With nothing to answer, an aggregator raises aggregates.Inapplicable.

ner

aggregates.ner(*, input, out, previous=None, labels=None, threshold=None, model=None)
SettingDefaultMeaning
labelsperson, organisation, location, product, event, dateThe kinds of entity to find. GLiNER accepts any label, such as ["drug", "dosage"].

Payload: entities (each text, label, chunk_ids, mentions), count, by_label, chunks_read, labels, model.

sentiment

aggregates.sentiment(*, input, out, previous=None, model=None)

model defaults to distilbert-base-uncased-finetuned-sst-2-english. Payload: per_chunk (each chunk_id, start_ts, end_ts, label, score, signed from -1 to 1), mean, positive_chunks, negative_chunks, turning_points, chunks_read, model.

summary

aggregates.summary(*, input, out, previous=None, llm=None)

Summarises the chunks in groups, then summarises those summaries until one remains, so it handles videos of any length. Payload: summary (at least 150 words, citing chunk ids like [3]), topics, setting, notable, chunks_read, reduction_levels, layers (each intermediate summary), word_count.

chapters

aggregates.chapters(*, input, out, previous=None, llm=None, embedder=None, max_spans=None, min_span_s=None)

The embedder places chapter boundaries where neighbouring chunks are least similar, and the LLM names and summarises each chapter. Times come from the grid.

SettingDefaultMeaning
max_spansnoneThe maximum number of chapters. The most similar neighbouring chapters are merged until the count fits.
min_span_s30The minimum chapter length in seconds. Shorter chapters are merged into their more similar neighbour. 0 disables this.

Payload: chapters (each title, summary, chunk_ids, start_ts, end_ts), count, covers_all_chunks, uncovered, segmentation (boundaries, their similarity and depth, and merges).

events

aggregates.events(*, input, out, previous=None, llm=None)

Reads 100 chunks at a time. Each event cites a chunk, and its times come from the grid. Payload: events (each what, kind of action, arrival, change or speech, chunk_id, start_ts, end_ts), count, windows.

entities

aggregates.entities(*, profile, input, out, previous=None, llm=None, embedder=None)
people = video.sightings(profile="people", answers=["yolo"])
aggregates.entities(profile="people", input=people, out=D / "answers" / "people.json",
                    llm=models.llm, embedder=models.embedder)

Entries are linked by the similarity of their identity fields' embeddings. Two entries in one answer are different subjects, so their similarity sets each video's threshold. The LLM then writes an account of each entity and marks contradicting observations as doubts.

Built-in profileLinks entries ofIdentityFrom the answers of
peoplepeopleappearance, clothing, plus the fixed attributesyolo, or any question with the people shape
objectsobjectsobject, appearanceobjects
textvisible_texttexttext

Payload: entities, each with entity_id, label, appearances, chunk_ids, start_ts, end_ts, observed_s, mentions (each sighting), account (the profile's fields, e.g. description, narrative, role) and doubts; also count, linked, narrated, together (pairs seen in the same chunks), and linking (the threshold and how it was set). Stored as entities.people.json. Your own profiles: add_profile.

link: entries you hold

Runs the linking step of entities on any list of entries, with no record, files or LLM; for example, on one description per tracked person, to find the same shopper across cameras.

aggregates.link(entries, *, profile="people", different=None, threshold=None, embedder=None) -> Linked
ArgumentDefaultMeaning
entriesrequiredDicts carrying the profile's identity fields: for people, appearance and clothing, and the fixed attributes when present. An entry with none of the identity fields is refused.
profile"people"A link profile, built-in or from add_profile; its rules and measures apply.
differentnonePairs known to be different subjects, as an N x N mask or a function of two indexes. The threshold is set from these pairs, and they are never placed in the same group.
thresholdthe profile'sA fixed bar instead. Needed when different is not given.
embedderOpenAIEmbedder()The embedder identity is measured in.
entries = [describe.ask(t.crops, "yolo", vlm=vlm).fields["people"][0] for t in tracks]

def overlap(i, j):                     # one person is not in two places at once
    a, b = tracks[i], tracks[j]
    return a.start_ts < b.end_ts and b.start_ts < a.end_ts

linked = aggregates.link(entries, different=overlap, embedder=LocalEmbedder())
for group in linked.groups:            # indexes into entries
    journey = sorted((tracks[i] for i in group), key=lambda t: t.start_ts)

It returns an aggregates.Linked with groups, threshold (the threshold used), calibration_pairs (the known-different pairs it was set from) and candidate_pairs (the pairs above it). The threshold is a z-score when the profile combines several similarities, as people does, and different is given; otherwise it is a cosine similarity.

custom

aggregates.custom(*, name, input, out, previous=None, llm=None, embedder=None, **settings)

Runs a prompt aggregator by name, either one added with add_prompt or a built-in one; custom(name="summary") is the same as summary(). Prompts of kind spans also take embedder, max_spans and min_span_s. See Custom prompts.

Several at once: aggregate()

aggregates.aggregate(*, out, models=None, database=None, previous=None, settings=None, **aggregators) -> Produced

Runs several aggregators, cheapest first. Each keyword argument names an aggregator, and its value is that aggregator's input.

done = aggregates.aggregate(
    out=D / "aggregates",
    previous=D / "aggregates",                    # reuse answers that are still current
    models=models,
    database=db,                                  # optional copy (see Databases)
    stats=video, speakers=video,
    ner=said, summary=both, chapters=both, events=seen,
    entities_people=people,                       # entities:people
    incident_report=seen,                         # a custom prompt, by its name
    sentiment={"spoken": said, "seen": seen},     # two answers: sentiment~spoken, ~seen
    settings={"ner": {"labels": ["person"]}, "chapters": {"max_spans": 4}},
)
done.artifacts                # {"summary": ".../summary.json", "sentiment~spoken": ..., ...}
done.stats["computed"]        # how many were run rather than reused
done.stats["skipped"]         # {"speakers": "needs a transcript ..."}
done.stats["problems"]        # database writes that failed
ArgumentMeaning
outThe folder for the answers. Each aggregator's input is saved in out/inputs/.
previousA folder of earlier answers (usually out).
modelsThe llm and embedder to use; None means the defaults.
databaseAlso export the answers, and embed the summary, chapters and entity accounts for aggregates.search.
settings{aggregator: {setting: value}}.
**aggregatorsEach aggregator by name (entities:people as entities_people), with its input: a Record, an excerpt, sightings, a saved input's path, or a dict of labelled inputs for several answers from one aggregator.

aggregates.validate(settings=None, models=None, **aggregators) takes the same keywords and lists every problem without running.

Reading answers

answer = aggregates.load(D / "aggregates" / "summary.json")
answer.aggregate_id          # "summary"
answer.tier                  # "llm"
answer.payload["summary"]
answer.stats["model"]        # "openai:gpt-6-luna": who wrote it
answer.inputs_fingerprint    # a hash of the text it read

aggregates.answers(D / "aggregates")      # ["chapters", "entities:people", "stats", ...]
aggregates.load_all(D / "aggregates")     # {id: answer}; an absent folder is {}

load(path) reads one answer, answers(directory) lists the answer ids in a folder, and load_all(directory) reads them all.

aggregates.answer(name, data, answer_id=None, llm=None, embedder=None, previous=None, settings=None) runs one aggregator in memory and writes nothing. previous is an answer to reuse, and answer_id sets the answer's id, such as "sentiment~spoken".

Reuse

An answer is reused when its input text, definition version and model key all match. Changing any of them, or a setting like max_spans, recomputes it. Reused answers are still written to out.

Several videos as one

aggregates.combine(*, records, out, video_id=None) -> Record
monday = aggregates.record(timeline="data/out/monday/timeline.json",
                           transcript="data/out/monday/transcript.json")
tuesday = aggregates.record(timeline="data/out/tuesday/timeline.json",
                            transcript="data/out/tuesday/transcript.json")

week = aggregates.combine(records=[monday, tuesday], out="data/out/week")
aggregates.summary(input=week.excerpt(transcript=True),
                   out="data/out/week/summary.json", llm=models.llm)

The videos are placed end to end on one timeline, with chunks renumbered, times shifted and speakers prefixed by video id. The result is written to out and returned as a record. Linking over it also links across videos, so lookalikes in different videos may be merged. aggregates.merge(parts, video_id=None) does it in memory; each part is a combination.Part(timeline, descriptions=None, transcript=None, manifest=None).

Searching aggregates

aggregates.search(query, level="source", limit=5, source_ids=None, database=None, models=None) -> list[dict]

When given a database, aggregate() also embeds three kinds of text, each searched at its own level:

levelFindsBy
"source"which videoits summary
"span"which part, with a time spaneach chapter
"entity"who or whateach linked entity's account
videos = aggregates.search("a busy checkout", level="source", models=models, database=db)
parts = aggregates.search("customers paying", level="span", limit=10, models=models, database=db)
who = aggregates.search("a man in a red cap", level="entity", models=models, database=db)

parts[0]["source_id"], parts[0]["aggregate_id"], parts[0]["item_id"]
parts[0]["start_ts"], parts[0]["end_ts"], parts[0]["content"]

It returns the best limit matches for query at that level, each a dict with source_id, video_ids, aggregate_id, item_id, level, content, start_ts, end_ts and ranks. Results from different levels are never mixed. source_ids limits the search to some sources. Use the same embedder the aggregates were exported with.

Looking up aggregators

aggregates.available()          # every aggregator id, built in and added
aggregates.about("chapters")    # "a table of contents: contiguous chapters ..."
aggregates.tier_of("ner")       # "local"
aggregates.kind_of("summary")   # "fold"; None for one written as code; "link" for a profile
aggregates.settings_of("ner")   # ["model", "labels", "threshold"]
aggregates.uses_embedder("chapters")   # True
aggregates.takes_inputs("stats")       # False: it reads a record

Lower-level functions: aggregates.build(name, llm=None, embedder=None, **settings) constructs an aggregator; aggregates.missing(aggregator, context) says why one can't run on a Context; aggregates.definition_rows(used) gives the definition rows a database stores. aggregates.REGISTRY holds the free aggregators, aggregates.RUNNERS the class per prompt kind, aggregates.TIERS is ("free", "local", "llm").
